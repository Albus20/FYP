## J11　企业作者　⏰ 10/10

**做什么**：用你 9/11 采的那张作者×年×机构大表（`raw\openalex_author_inst_years.csv`，77 MB），把作者按署名机构的类型拆开，数港星两地「在企业里发表论文的研究者」。机构类型有大学、医院、企业等。规则先写好了，见 `docs/企业作者口径_2026-10-04.md`。

**怎么跑**：在 `data_repo` 文件夹里运行。用 PyCharm 的话，在 Parameters 里分别填 `--fetch`、`--build`。

```
$env:COLLECTOR_NAME="賈贇"
python scripts\company_authors_build.py --fetch
python scripts\company_authors_build.py --build > logs\company_authors_build_2026-10-XX.txt
```

- `--fetch` 会联网向 OpenAlex 取港星两地的全部机构及类型，约 20–40 次调用，几分钟。
- `--build` 不联网，一两分钟。开头有两道自检：
  - 「自检一」核对大表是不是 9/11 那一版；
  - 「自检二」核对算出来的本地作者数与研究者存量对得上。
- **任何一处出现 ⛔ 就停下**，把屏幕输出截图发组长，不用自己改。

**回传**：

- `raw\openalex_institutions_hk_sg.csv`
- `manifests\openalex_institutions_hk_sg.csv.manifest.json`
- `manifests\openalex_institutions_hk_sg.csv.requests.tsv`

## J12　BigQuery 两条查询　⏰ 10/12

**为什么做**：

- 导师会上答应过补充分析 S3：把企业专利延到 2024 年，看人才增长最快的 2022 年以后有没有体现在专利上。规则见 `docs/RQ2补充分析计划_2026-10-02.md`。
- 红队检查要查清「看不见的专利」：只在内地申请的，以及挂在港校深圳研究院、NUS 苏州研究院名下的。我们现有数据按申请人国别筛选，这两类都漏掉了。

**怎么跑**：跟 8/27 跑专利那次一样，每条都按下面做：

1. 打开 BigQuery 控制台，新建查询，整段粘贴 SQL。
2. 运行前看右上角「This query will process X GB」。**超过 100 GB 就先别跑**，截图发组长。
3. 运行完点「Save results → CSV (local file)」，按下表改名，放进 `data_repo\raw\`。

| 顺序 | SQL 文件 | 导出成 | 估计扫描量 |
|---|---|---|---|
| 1 | `sql\patents_bigquery_s3_2024.sql` | `raw\patents_families_raw_s3.csv` | 约 15–20 GB |
| 2 | `sql\patents_bigquery_invisible_univ.sql` | `raw\patents_invisible_univ_families.csv` | 约 30–60 GB |

两条加起来远低于免费额度（每月 1 TB）。

4. 写 manifest（在 `data_repo` 里）：

```
$env:COLLECTOR_NAME="賈贇"
python scripts\manifest.py add raw\patents_families_raw_s3.csv --url "https://console.cloud.google.com/bigquery?p=patents-public-data&d=patents&t=publications" --query "sql/patents_bigquery_s3_2024.sql 原样运行" --by "賈贇"
python scripts\manifest.py add raw\patents_invisible_univ_families.csv --url "https://console.cloud.google.com/bigquery?p=patents-public-data&d=patents&t=publications" --query "sql/patents_bigquery_invisible_univ.sql 原样运行" --by "賈贇"
```

5. 记下两条查询各自**实际扫描了多少 GB、导出了多少行**，回传时写在消息里。

**回传**：上面两个 CSV，以及 `manifests\` 里对应的两个 `.manifest.json`。SQL 报错的话，把错误截图发组长，不用自己改。

## 拿脚本与交付

- **拿脚本**：组长直接发文件给你（或从 https://github.com/Qiuu2/FYP 的 `scripts/` 单独下载那一个文件），放进你原来的 `data_repo\scripts\` 覆盖同名文件。不需要 git。
- **在哪跑都行**：上面的命令是在 `data_repo` 文件夹里跑的写法；在 `scripts` 文件夹里就去掉 `scripts\`；用 PyCharm 就在运行配置里 Parameters 填 `--full`、Environment variables 填 `COLLECTOR_NAME=賈贇`。如果你的 `data_repo\.keys.env` 里写了 COLLECTOR_NAME 和 OpenAlex key，新脚本会自己读，不用再设。
- **交付**：完成一项就开一个 GitHub pull request（10/2 这样交的很好：只加文件、不改别人的文件），或者打包发给组长。文件名不用改。
- **请求日志（.requests.tsv）放 `manifests/`，不要放 `raw/`**：`raw/` 里每个文件都必须有 manifest，多出一个日志文件会让 `manifest.py verify` 报错。J4-2 的请求日志 9/30 已经收到并放进 `manifests/` 了，不用再发。
